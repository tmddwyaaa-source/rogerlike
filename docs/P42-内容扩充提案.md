## 1. 数值与池子改动（批次 1）

### 1.1 技巧 −0.20 → −0.15
- 常量：`frontend/src/game/weapons/index.js` 的 `CHARGE_UPGRADE` `0.2 → 0.15`（**M2**）
- 文案：`frontend/src/ui/constants.js` 的 `技巧` desc → `蓄力时间 −0.15`（**M6**）
- 断言：`combat/selftest.mjs` 里以 −0.20 推的期望值全部改 −0.15（含"3 次到 0"这类条数断言 → 改成 5 次）；`ui/selftest.mjs` 文案断言同步
- 既有链保留：`chargeMax <= 0` 时「技巧」退出池、「唯快不破」才进池

### 1.2 唯快不破：高级 → 普通
- `ui/constants.js`：去掉 `tier: 'advanced'`；高级池 **10 → 9** 项（**M6**）
- 前置保留：仅 `chargeMax <= 0` 时出现（现有 `availableUpgrades` 逻辑不动）
- 断言：`only_fast` 的 `tier !== 'advanced'`，且仍受 `chargeMax <= 0` 门控

### 1.3 强化射击：游侠专属
- `ui/session.js` 的 `availableUpgrades()`：按 `charId` 过滤，`empower_shot` 仅 `ranger`（**M6**）
- 文案：`ui/constants.js` desc 去掉"其他角色 +15"分支，只留游侠版
- 断言：`availableUpgrades({charId:'warrior'})` / `'mage'` 不含 `empower_shot`；`'ranger'` 含
- 连带：天行健对战士/法师的计入项 11 → 10（档 8 仍可达，无需改阈值）

### 1.4 高级出现机制：文档改为代码口径（**M1**）
代码实现是 `isAdvancedOffer(level)`：**角色等级是 5 的倍数时，三选一必出 1 个高级项**，其余槽位各有 30% 概率（`ADVANCED_OFFER_CHANCE`）。设计表/GAME-SPEC 现有的"每第 5、10、15… **次三选一**有 30%"是旧口径，本次改为代码口径。

## 2. 新增普通升级（批次 2）

### 2.1 荆棘 `thorn`
- 效果：**受击时**对 **4 身位（4 × BODY = 88px）** 内敌人造成 `攻击 × 150%`；每多 1 层 **+50%**（1 层 150%、2 层 200%、3 层 250%…）
- 结算口径：**掷暴击**（走与武器一致的暴击率/暴击伤害）、**飘伤害数字**、**不触发**点燃/减速/击退/穿透
- 触发源：`createPlayer({ onHurt })`（`game/player/index.js`，无敌挡掉不触发）
- 分工：**M2** 在 `game/combat/index.js` 提供 `thornBurst(origin)`；**M1** 在 `match.js` 把 `onHurt` 接到 `thornBurst`
- 计入羁绊：生生不息
- 断言：1 层伤害 = `攻击×1.5`；2 层 = `攻击×2.0`；范围边界（4 身位内命中、4 身位外不命中）；可暴击（固定暴击率 100% 时伤害 = ×暴击倍率）
- 素材：**待定** → 局内空白方块

### 2.2 滋补 `nourish`
- 效果：每击杀 **1000** 个敌人回 1 心；每多 1 层，阈值 **−100**（1 层 1000、2 层 900…）

- 满血时：**照常计数、不回血**，不做囤积
- 分工：**M6**（击杀计数在 `ui/session.js` 的 `addKill`，回血走既有 `player` 通道）
- 计入羁绊：生生不息
- 断言：阈值序列 1000/900/800…；下限 100；跨阈值时回 1 心；满血不回但计数继续
- 素材：**待定** → 局内空白方块

## 4. power「激发力量」（批次 3，新子系统）

### 4.1 触发与候选
- 触发：**每 10 级**（Lv.10 / 20 / 30…）——先走完当次常规三选一（或二娃四选一），**再单独弹一次 power**
- 候选池：游侠 = {连射 `rapid`、贯穿强化 `pierce_amp`、定神 `steady`、sp-power `sp`}；战士 / 法师 = {sp-power}
- 唯一性：连射 / 贯穿强化 / 定神 **各只能拿一次**；sp-power **可无限叠**
  - 游侠拿满三个唯一项后，power 池只剩 sp-power
- 卡片名统一显示「激发力量」；**无语义图标 → 空白方块**
- **强制选择**：不能跳过、不能 ESC 关闭（连点空白处不生效）

### 4.2 四个效果
| id | 名称 | 效果（已确认口径）|
|---|---|---|
| `rapid` | 连射 | 不蓄力攻击时 **50%** 概率额外发射 1 发箭矢；蓄力攻击 **100%** 额外发射 1 发。**额外那一发自带 0.75s 冷却**（与武器 0.48s 间隔独立）。额外一发**吃**散射/开眼了/大娃等既有加成 |
| `pierce_amp` | 贯穿强化 | 每穿过 1 个敌人本次伤害 **+50%**；穿透 **+1** |
| `steady` | 定神 | **静止 0.3s** 后，下一次攻击 **暴击率 +100**（即必暴），只作用于**下一次**攻击 |
| `sp` | sp-power | 角色攻击 **+20**（可无限叠）|

- power 效果**不计入任何羁绊**
- 回忆里记录为一条：空白图标 +「激发力量」，悬停显示本次拿到的效果名

### 4.3 卡牌界面（像素风扩展版，用户描述 + M1 细化）
**阶段**：常规三选一结束 → 单独进入 power 屏（不与升级卡同屏）。

**布局与运动**
- 空白卡牌（复用 `.rl-frame` 像素边框 + 空白方块图标区）从**屏幕左缘外侧**向右漂入，**横穿屏幕后从右缘外侧回到左侧继续**，无限循环（左进右出，不结束）
- 同屏卡牌数 = 候选池大小（游侠 4 张、战士/法师 1 张）
- 漂移速度 **90–140 px/s**（可调常量）；每张卡以 **正弦上下浮动**（幅度约 6–10px）且相位错开，避免整齐划一
- 卡与卡之间保持至少 1 张卡宽的间距，避免重叠

**底部提示**
- 屏幕下方居中一行**纯像素文字**（**无文字框**）：「选一张」
- 使用局外标题同款做法：像素字体 + 1px 深色描边，不做渐变/圆角

**选择与揭晓**
1. 点击某张卡 → 其余卡**向左右边缘加速飘走并淡出**，不再可选
2. 被点中的卡**减速移动到屏幕中央**
3. 中央卡**横向翻转**（`scaleX: 1 → 0 → 1`，中点切换正/反面；像素风用 `steps()` 分两段，不做平滑渐变）
4. 正面显示：效果名（连射 / 贯穿强化 / 定神 / sp-power）+ 一行效果说明；图标区保留空白方块
5. 停留 **0.6s** 后可点击/按键跳过，随后淡出回到对局

**实现要点（派工参考）**
- 卡牌运动与翻转用 CSS transform + `steps()` 过渡；候选池、唯一性、已拿集合由 `ui/session.js` 管理
- 新增组件建议 `frontend/src/views/PowerView.vue`（或扩展 `UpgradeView.vue`），由 `GameShell.vue` 在 `phase` 上分派
- 新 phase（如 `power`）：`playing` 以外整帧停的既有规则沿用

### 4.4 分工
- **M6**：常量池、`phase`/状态、`PowerView.vue`、唯一性/可叠逻辑、回忆记录、selftest
- **M2**：连射（额外弹体 + 0.75s CD）、贯穿强化（穿透加伤）、sp-power（攻击 +20）
