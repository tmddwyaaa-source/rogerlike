## 2. 阶段角色（环内，空间与阶段正交）

| 角色 | 允许 | 禁止 |
|------|------|------|
| **斥候** | 只读调查、列路径与可疑点、建议最小范围 | 改代码、声称已修好、改状态 |
| **主力** | 最小改动实现；交计划、diff、本回合终端原文 | 越界、自标 done、开游戏预览、只交 PASS 摘要 |
| **搜剿** | 只验收挑刺；施工窗没跑终端则 fail | 凭感觉放行、顺手改实现 |

环内：**斥候 → 主力 → 搜剿**；搜剿 fail → 主力↔搜剿；同一卡点最多 **4** 次，第 4 次仍 fail → 硬停写 `docs/BLOCKERS/{窗号}-{短标题}.md` 并点名下一步。

## 3. 铁律（查收与收口）

1. **只有 M1** 能标 `done`、能开游戏实机；子窗口禁止开游戏、禁止自标 done。
2. **工人跑完不会自动交 M1**，fail 也不会自动重开——中间那一跳由用户传话（「{窗号} 已完成，请查收」）。
3. **M1 本窗重跑**该窗验收命令才算通过；磁盘核对用 mtime 判定本环改动边界。
4. 任务状态只走 `transition`；直接编辑 `manifest.json` 不算收口。窗口状态在 `.task/round.json` 的 `window_status`。
5. **亲自微修订**必须用户点名并同意；未点名就派对应 M/C。
6. 用户每条新需求必须写入 `source_refs` / `source_requirements` 并映射到带 `verify` 的 R 项，否则 `REQUIREMENT_COVERAGE_FAIL`。

## 4. 任务控制层（`.task/`）

```text
.task/
├─ round.json                 # 本轮派工 / window_status / gears / hook_supervision / subagents
├─ hook-runs.jsonl            # 宿主 stop 证据（≤100 行，须 gitignore）
├─ TASK-xxx/manifest.json     # 任务状态与 R 项（唯一状态源）
├─ TASK-xxx/worker-report.json
├─ TASK-xxx/verify-report.json  # 仅独立验收路径
├─ TASK-xxx/rerun.json        # Full Gate 写入，禁止手改当证据
└─ TASK-xxx/evidence/
```

**策略表（唯一实现 `verification_policy()`）**：

| 条件 | 收口路径 |
|------|----------|
| `risk=low` 且 `attempt<2` 且未设 `verification_required` | `worker_done → integrated`（M1）→ `done`（M1） |
| 其余（medium/high、`attempt≥2`、显式要求独立验收） | `worker_done → verifying → verified`（verifier）→ `integrated → done`（M1） |

常用命令（`--root` 必须在子命令前）：

```text
py -3 scripts/taskctl.py selftest
py -3 scripts/taskctl.py --root D:/Cursor_projectt/rogerlike round-init ROUND-001 M2 C1 --task M2=TASK-001
py -3 scripts/taskctl.py --root D:/Cursor_projectt/rogerlike brief TASK-001 --role worker
py -3 scripts/taskctl.py --root D:/Cursor_projectt/rogerlike status --markdown --write
py -3 scripts/taskctl.py --root D:/Cursor_projectt/rogerlike audit-round
py -3 scripts/taskctl.py --root D:/Cursor_projectt/rogerlike transition TASK-001 in_progress --actor M1
py -3 scripts/taskctl.py --root D:/Cursor_projectt/rogerlike handoff
```
