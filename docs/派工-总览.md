## ⚠️ 两条正交的轴，别混成一条

| 轴 | 是什么 | 取值 | 变不变 |
|----|--------|------|--------|
| **空间轴：窗号（身份）** | 这个窗口**是谁**、守哪块长期模块 | `M1`~`M10`、`C1`…（M1 主导、唯一收口） | **长期稳定** |
| **阶段轴：环内角色** | 同一窗在**同一个任务**上依次走的三个阶段 | **斥候 → 主力 → 搜剿** | **每环、每个任务走一遍** |

- `斥候 / 主力 / 搜剿` **不是身份**，不是长期扮演的角色：
  - **斥候**：只读摸底、列路径与可疑点、给最小范围（**不改代码**）
  - **主力**：最小改动实现，交计划 + diff + **本回合终端原文**（不自标 done）
  - **搜剿**：对自己刚交的东西挑刺自检（复跑、边界、非平凡性）；fail 就 主力↔搜剿 迭代
- **独立验收**是**任务维度**的约束（`verify-report.json` 的 `reviewer` **≠ 实现该任务的窗口**），不是某个窗的身份。
- 同一卡点最多 **4** 次；第 4 次仍 fail → 硬停并写 `docs/BLOCKERS/{窗号}-{短标题}.md`。

## 全局纪律（每个窗都适用）

1. **只改自己任务的 `allowed_paths`**（见 manifest）；不要碰别人的模块，不要跑 `npm run build`（由 M1 集成时统一跑），**不要打开网页预览**（只有 M1 能开）。
2. **必须在本窗终端跑验收命令并贴输出原文**；一行 `RESULT PASS` 只要是命令打出来的就是全文。命令文本**逐字**来自 manifest 的 `verify_cmd`，不得改写。
3. 本机 **PowerShell 是 5.1，不支持 `&&`**：把 `verify_cmd` 逐字写入 `.cmd` 文件用 `cmd /c` 执行；`.cmd` 必须 **UTF-8 无 BOM**（否则 node 收到乱码中文、断言标题匹配失败）。
4. **先自证伪**：新断言先写、实现未加时跑一次，确认它们 FAIL（证明不是空壳），再加实现转 PASS；两次输出都留证据。
5. 完工**不自标 done**；施工窗只交 `worker_done`，独立验收窗交 `verifying`/`verified`，`integrated`/`done` 与开游戏**只有 M1**。
6. 完工话术：对用户说「**{窗号} 已完成，请主导窗口查收**」。工人跑完**不会**自动交给 M1，fail 也**不会**自动重开——中间那一跳由用户传话。
7. 证据放 `.task/{任务号}/evidence/`；报告写 `.task/{任务号}/worker-report.json`（或 `verify-report.json`）。
   ⚠️ `worker-report.tests` **只写 manifest 的验收命令**——门禁会重跑 `tests` 里的命令，交叉核对请放 `notes`/evidence，不要写进 `tests`。
